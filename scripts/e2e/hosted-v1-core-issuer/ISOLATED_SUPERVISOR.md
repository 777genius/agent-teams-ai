# Inert Docker isolation fixture

`isolated-supervisor.py` is a test-only root issuer. It is not connected to the Owner CLI, Product runtime, or an agent effect path. Its only container command is `/bin/true` from a root-selected digest-pinned synthetic image. `effectEnabled` is always false.

The root issuer creates empty, mode `0700` workspace and profile directories directly under root-owned lease parents, then calls `issue_lease()`. `dispatch()` accepts an exact six-field `Start`, `Observe`, `Stop`, or `Reconcile` request with opaque lease or handle and generation IDs. It rejects caller paths, Docker flags, unknown fields, consumed leases, stale generations, and conflicting operation replays. No socket is exposed. An authenticated bounded transport and persistent recovery ledger are prerequisites for a future Owner adapter.

`Start` creates a container with Docker's default private PID namespace, explicit private IPC and no network, a read-only root filesystem, exactly two admitted mounts, `cap_drop=ALL`, no-new-privileges, a root-owned SHA-pinned deny-default seccomp profile, an explicit AppArmor profile, and fixed CPU, memory, and PID limits. It checks the effective seccomp JSON and other Docker settings before and after `start`. The generation label and opaque name are recorded before `docker create`; a timeout or malformed create reply returns an unresolved handle without another create or a guessed cleanup. `Stop` and `Reconcile` require the exact generation and confirm `Running=false` and `Pid=0` before removing the container. A lost remove reply is resolved only after Docker reports the known container ID missing. A create with no known ID and no discoverable name remains unresolved for root audit. The synthetic test image's `/bin/true` is the only executable supported by this fixture.

The root issuer must independently select a reviewed image and a working seccomp/AppArmor policy. The Python unit tests use a fake Docker runner and a deliberately non-runnable deny-default seccomp sample; they prove admission and failure behavior, not kernel isolation. A disposable Linux Docker test must verify actual applied policy, mount inaccessibility for Owner state and Docker socket, and zero surviving processes. Official OpenCode, local model traffic, and agent commands remain disabled until the Owner container adapter and one-use effect capability are implemented and reviewed.
