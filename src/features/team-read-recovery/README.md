# Team read recovery

The renderer entrypoint owns the messages-head handoff behind an older-page read. A queued caller observes the head read actually performed. If the older page detects a changed feed, it releases older ownership and starts that same queued head before awaiting it, avoiding a self-wait cycle. Settlement retires only the matching queue record.

The handoff preserves existing store projections, error behavior and context/team epoch guards. Recovery transport is described below; deferred retry credit and worker admission policy remain separate accepted-plan work.

The contracts/main/preload/renderer entrypoints carry validated plain worker failure metadata over the existing four read channels. Worker cooldown owns the recovery ID and retryAt; raw read results are optional and legacy/browser APIs retain their signatures and behavior. Recovering, busy, fatal and disposed worker outcomes stop heavy-main fallback on all five worker-consuming paths. Renderer-local errors retain human message and validated metadata through unwrapIpc. This transport checkpoint does not schedule retries, add admission numbers or change TaskChange worker lifecycle policy.

`core/application/TeamDataReadWork.ts` owns live full/thin retrievals, refresh tokens and queued/fresh flags in the captured context and team scope. A different scope starts its own retrieval; a late release or queue cleanup cannot remove replacement ownership. The renderer store captures scope before physical joins and checks automatic-poll admission through the live store getter. Empty work owners are pruned, and completed snapshots remain in the store.

This data-scope checkpoint preserves thin selection followed by post-paint full enrichment, the queued enrichment's early acknowledgement, force-fresh bypass and the legacy full-refresh completion contract. It does not yet provide an observable full-data fresh successor, immediate connection/subscriber disposal or cooldown/retry scheduling.

`main/infrastructure/OwnedReadDescriptors.ts` owns original callback file acquisitions through successful explicit close, including opens delivered after retirement and reads or descriptor metadata still awaiting their original callback. Close failures remain UNKNOWN and are never retried blindly. `core/application/PhysicalReadScope.ts` keeps logical results separate from physical completion and admits late cleanup only beneath a live physical parent. These are producer foundation ports; Worker integration, atomic publication/durability integration, source-owner transitions and full observed-successor enablement remain pending.

The physical foundation bounds concurrent acquisitions and per-descriptor reads/metadata/write/sync operations before allocating buffers. Ambiguous dispatch and close faults suspend owner admission and retain a minimal lease/fault identity. `readOwnedUtf8` requires a shared descriptor owner, captures limits before awaiting, and closes only its acquisition on completion or timeout; sibling reads retain their owner. Its physical port is separate from the existing logical timeout. Supported composition and broader resource qualification remain pending.

`OwnedPathOperations` captures stat/lstat/readdir/mkdir/rename/link/unlink arguments and observes their original callbacks. Retirement preserves completed mutation results while retaining physical work. These path ports are not yet wired to source authority; recursive deletion remains unqualified.

Descriptor `write` copies bounded input bytes before dispatch and reports the original partial byte count; callers must supply the full write loop and flags/mode policy. `sync` retains the descriptor through the original fsync callback. Fault normalization tolerates hostile getters/coercion and cannot prevent UNKNOWN ownership or physical-chain cleanup. These are raw ports, not integrated persistence or durability guarantees.

`writeOwnedBytes` captures a bounded complete payload and options, completes partial writes with explicit progress checks, optionally performs strict fsync, and reports completion only after original close. It preserves explicit creation modes and flags. Atomic publication, best-effort durability diagnostics and service/source-owner integration remain separate required work.

`syncOwnedPath` synchronizes files or directories through the shared main-owned descriptor pool. It preserves strict storage failures and the existing unsupported-directory policy, and returns explicit best-effort diagnostics only after confirmed close. An UNKNOWN close always rejects, including best-effort mode. Existing persistence helpers and Worker paths are not yet migrated to this port; atomic publication and full source-owner integration remain pending.
