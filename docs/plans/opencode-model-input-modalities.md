## Concrete catalog wiring constraints from source

The existing passive catalog hook `runtime-provider-management/renderer/hooks/useOpenCodeProviderModelCatalog.ts:mapCatalogModel` currently reconstructs `inputModalities` from a separate passive status row, falling back to `['text']`. Extending only the DTO will therefore not work: mapping must carry the new declaration directly from the selected provider-model row. Do not borrow metadata from an unmatched status row.

The existing `loadOpenCodeScopedCatalog` already validates provider identity, qualified model IDs, pagination, duplicate rows, cancellation and freshness. Reuse its identity/request conventions instead of adding a parallel validator. Its `MODEL_CATALOG_FRESHNESS_MS` is two minutes. Catalog timestamps in runtime status can have `staleAt === fetchedAt`; do not use that unrelated timestamp to permanently disable attachments or introduce polling. Choose the existing scoped cache freshness and resolve authoritative admission at send.

Runtime120 V2 passive output is `src/features/runtimeProviderManagement/adapters/opencode/OpenCodeV2ProviderManagement.ts:loadOpenCodeV2ProviderModels`: native `owner.models()` rows are mapped to provider models but their declarations are discarded. V2 runtime status instead uses normalized `read.models[].input` in `src/services/opencode/catalog/OpenCodeV2RuntimeStatus.ts`. The exact runtime120 `OpenCodeV2ReadStatus.ts:readModel` validates native `capabilities.input` as an array without fallback, so that V2 input has declaration provenance. Its native provider-model rows also use an input array. Legacy `raw.capabilities.input` uses a Boolean record; do not pass the V2 array through a legacy record-only parser. Preserve explicit empty arrays as known none. Legacy provider-management mapping is `buildRuntimeProviderModel` in `OpenCodeProviderManagementAdapter.ts`. These are dependency changes only; do not alter authentication, execution proof or launch readiness.

## Required contract decisions

1. Reuse existing runtime catalog and add only the minimal optional declaration metadata required to preserve unknown vs explicit known input. Prefer an additive nullable field compatible with old runtimes; absent/null is unknown, explicit `[]` or `['text']` is known non-image/non-video. Do not reinterpret a legacy fallback `['text']` as an authoritative declaration. Actual runtime mapping must preserve declarations in both legacy and V2 where those catalog paths are used. The binding field is `RuntimeProviderModel` / `RuntimeProviderModelDto.declaredInputModalities?: readonly string[] | null`; concrete wiring follows below.
2. Pure capability resolution accepts actual scoped model declaration, not runtime DTOs or async services. Image/video support are independent: image-only, video-only, both, neither, unknown. Remove all OpenCode model-name support sets. Missing/malformed/foreign/conflicting declaration is unknown. Unknown native media is blocked with a clear distinct explanation; text and existing reference files remain usable.
3. Identity is project scope + OpenCode source provider + exact runtime model identity. Use existing qualified model identity utilities. Do not lowercase arbitrary model IDs or strip openai/openrouter prefixes; two providers' same short model name cannot authorize one another. Bare/default model selection must resolve through existing effective runtime selection; no guessing from first catalog row.
4. Renderer loads only on relevant OpenCode recipient/project/model change using existing scoped requests/cache; no fetch per keystroke, paste, attachment, or validation iteration. Loading/error/missing or already-invalidated catalog yields unknown. Reuse existing freshness on lookup; add no periodic timer or per-render network request. Late response for another recipient/project cannot enable current media. Draft attachments survive switches; unsupported ones block Send with a reason rather than being silently dropped.
5. Main resolves the current recipient model and project itself at send/delivery. Catalog errors produce a clear nonretry-loop refusal, not silent media omission. Revalidate against the resolved target at the last existing pre-dispatch boundary; pass that same resolved capability into serialization so the adapter cannot fall back to its old name list. Do not fetch another catalog inside the pure serializer or add duplicate uncached catalog requests for one send; reuse the existing scoped catalog port/cache and pass a short-lived resolved value through the current call chain. Catalog change between UI and send may legitimately refuse; never deliver to an old model or trust stale renderer evidence.
6. Custom group chats currently support text only; preserve that behavior. Validate independently only on existing supported multi-recipient media paths; do not add group-media fanout. The current manual queue is text-only (`useDirectMessageQueue` rejects draft attachments and enqueues `attachments: []`); preserve that behavior and the queued recipient. Do not add queued-media support. Native media must still validate the current recipient at every existing direct send. Existing archive/read-only rules remain untouched.
7. Do not persist a duplicated capability snapshot into team/member config or message history as authority. Do not introduce silent reference conversion for unsupported images/video. Already-reference arbitrary files retain their existing route and limits.
