## Что допускается переключать

- B — private test-only SDK package/harness. Его assertions не допускают production team и не подтверждают C/E.
- D — только кластеры с разрешёнными imports/ports и сохранённым поведением. Смешанные task/bootstrap writers нельзя переносить как transport.
- E — новая sandbox-команда целиком у нового owner после admission; запись, чтение и подписки переключаются вместе. Legacy runs остаются у прежнего owner.
- F — ни одна строка этой матрицы не остаётся без проверенного преемника или явно принятого disposition. Неучтённый файл и отрицательный поиск imports не разрешают удаление функциональности.

## Оставшиеся условия C/E

В исследованном runtime `origin/main` snapshot `efd3348f361fa6af84953325af5c0d2d8677d14a` действующая программа разрешает Codex ordinary path, сохраняет contained-turn frozen и исключает текущий Claude rewrite/interactive session reuse/approvals. Поэтому B оформляется отдельным experimental package, а C требует scoped successor/admission для интерактивного пути; расширять frozen production feature нельзя.

У Orchestrator обязательны пять implementation readiness gates и accepted owning decisions. Наличие схем, предложенного владельца или успешного fixture не меняет их статус. До admission можно подготовить exact first-slice contract/failure fixtures. Product-visible forks и принятие ADR требуют указанного в репозитории решения владельца; агенты не выставляют `accepted` самостоятельно.

Полный end-to-end результат плана остаётся недоказанным до реального runtime → Orchestrator → desktop workflow и полной capability matrix. Отчёт о B должен отдельно назвать synthetic/package/live доказательства и оставшиеся C–F, а не объявлять весь план завершённым.

Настоящая provider authentication/inference и защищённое закрытие произвольных внешних writers этими native-проверками не доказаны. Эти факты уточняют частичную реализацию строк матрицы, а не закрывают их целиком. Несколько участников и реальная доставка сообщений — следующий N1; Work lifecycle/assignment/dependencies/review — N2. Group/cross-team, approvals, context/recovery, attribution, provider access и F сохраняются в обязательном backlog. Новые срезы должны пройти свои owning admissions и проверки.

Владелец явно сообщил отсутствие тестового Claude-доступа и поручил продолжать автономно на fixtures/mocks. Поэтому real Anthropic/auth не проверен и не требуется для synthetic C–F; реальная provider qualification остаётся явно недоказанной, без чтения пользовательских credentials.
