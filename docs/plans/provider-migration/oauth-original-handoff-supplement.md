## Already covered; retain rather than reimplement

The external commits now compare the complete original receipt before ordinary publish, completion publish, and both cleanup publications. A successful write alone advances entry.saved; missing or changed originals and uncertain ordinary writes suppress later cleanup writes. Correctly selected cancel schedules the original cleanup when its initial read is missing/corrupt/conflicting. Five new external tests cover expiry with missing/replaced originals, mutation/deletion during blocked close, late completion over a replaced original, and missing initial cancel. Keep those tests unchanged and retain their proven behavior. Do not replace the owner, introduce a second journal authority, or duplicate this suite.

## Remaining source-confirmed gaps

1. authorize and finish still call only assertBound immediately before and after native.authorize/native.complete. Synchronous onProgress can change/delete the durable original between authorizing/completing publication and the native handoff. An original deadline can also expire before its timer runs. Per-write checks occur too late to prevent that handoff. Existing live original/deadline checking must cover both sides of those native awaits.
2. The external stop changes a conflicted/uncertain live entry immediately to held while native.close is pending. This regresses G1b's existing blocked-close assertion: ordinary read remains cancelling during physical cleanup; retained completion replay uses the durable original and reports held. Preserve these distinct projections without writing over uncertain bytes.
3. In cancel, a valid replacement receipt can match a foreign caller's profile/config while the active entry still belongs to the original selector. captured is undefined, but the later stop(entry) still closes the original. complete has the same branch: after reading the valid foreign replacement it calls the active entry's live guard and can close it. Both APIs need the same early exact-active-selector refusal, before reading or mutating anything; cold reads/replay with no active entry keep existing behavior.
4. authorization also locates the active entry only by operation ID. A valid replacement can therefore expose the original private authorization URL to a foreign selector, and a same-selector changed receipt or expired original can still supply a URL that Main will open. This private read needs a pure original/deadline disclosure gate; it must not start native cleanup.
5. Both stop catches currently label a writer-check failure as publication uncertainty even though store.write was never attempted. Keep the conservative hold, but distinguish admission/read refusal from actual write uncertainty. A transient first writer failure must never allow the second cleanup write merely because the writer recovers during native.close.

## Narrow implementation over the external owner

Only packages/legacy-agent-host/src/management/OAuthOperationOwner.ts and the existing packages/legacy-agent-host/tests/management-oauth.test.ts change. No schema, provider adapter, native pin, transport, generic digest, public snapshot, fingerprint algorithm or stored legacy byte change. The external durable-cleanup test remains untouched.

Reuse the existing stored-original comparison and live guard. Make the low-level comparison usable with an explicit immutable expected predecessor and free of cleanup recursion: current writer, exact active entry, no existing receipt-conflict/publication-unknown fence, then full durable-record equality. It must work when stop has retired/sealed the capture and must not call assertAdmission, select a current profile, inspect expiry, emit, await or invoke native code. Missing/corrupt/wrong-kind/replaced reads set receiptConflict; writer/entry admission refusal does not fabricate an attempted-write flag.

A small shared write boundary is justified because ordinary publish, publishCompletion and both stop writes must all distinguish pre-write refusal from commit-then-throw. Run the original comparison synchronously immediately before store.write, with no await between them. Only an exception from the attempted store.write sets the renamed private publicationUnknown flag. Successful publication alone advances the expected durable predecessor. Keep the initial claim's existing attempted-write boundary unchanged.

The high-level existing live currentness/deadline guard catches original-record-check refusal, schedules the same original stop before propagating, and then checks the original expiresAt. Call it immediately before and after native.authorize/native.complete, retaining the actual write check too. This closes handoff/deadline races without moving cleanup into the low-level guard. Existing explicit/browser admission, pending-token A→B loop and algorithm selection remain. Retained replay remains outside effectful live guards and keeps close=false.

In stop, retain its one installed closing promise and mandatory abort/close-once behavior. Keep a local immutable expected predecessor captured before any live projection changes. Build cancelling separately, attempt the guarded write, and advance expected only on success. Maintain a local publicationAllowed boolean; ANY first guard/write failure clears it, including writer/entry admission refusal. Preserve entry.saved as the existing live cancelling view while cleanup is pending, but never use an uncommitted live projection as expected durable data. Always call original native.close even after a read/writer/write failure. After the await, only if publicationAllowed remains true, compare the last successful predecessor again and attempt the terminal write. Any refusal or unknown write leaves live custody held and prevents subsequent writes. Original bytes stay untouched by later code.

Do not manufacture cold holds by rewriting a released record. A completed write after native.complete(true), or a terminal stop write after clean close, can commit resourceHeld=false and then throw. Live custody conservatively holds; cold recovery follows the actual valid durable bytes. Test and report that distinction explicitly.

In cancel, complete and authorization, after finding entry and matching the supplied original operation/profile/config, reject entry && !captured with conflict before the original read. Wrong selectors must not fence or close that active capture even when they match a replacement file. For correctly selected cancel's missing/corrupt/conflicting initial read, preserve the external behavior: schedule the original single stop and immediately propagate refusal; do not await blocked cleanup before rejecting. Ordinary successful cancel continues to await its original close, including after current profile drift.

For authorization only, keep the existing waiting/live phase checks and assertBound, then run the pure full-original check and refuse if the original deadline elapsed before returning any private payload. Do not invoke the effectful live completion guard: a matching receipt mismatch may fence publication, but this read itself performs no close, write, stop or native call; expiry only refuses. The original timer or a later original close owns physical cleanup. A foreign selector is refused before the read and does not even fence the active entry. Generic read and retained completion replay remain unchanged.

## Named finite tests on the exact integrated baseline before fixing production

Use the existing real FileManagementCommandStore fixture. Its counters must increment before phase assertions so an invalid native handoff cannot be hidden by a fixture assertion. Add only bounded hooks and controlled promises; no native provider runs.

- Progress handoff: authorizing/completing onProgress deletes/replaces/corrupts the original or advances mocked Date to expiresAt before the timer runs. Assert zero ensuing native authorize/complete calls, original cleanup once, unchanged bytes/absence, and held live custody.
- Post-await deadline: release original authorize/complete after mocked Date reaches expiresAt without executing the timer. No waiting/completed publication over the expired claim; original deadline reason/cleanup remains truthful.
- Foreign selector: validly replace profile or config while the original is live, then call cancel, complete and authorization using the replacement selector. All three APIs refuse immediately, with zero close/native/journal effects. A later correctly selected close still cleans the original and preserves replacement bytes.
- Private authorization read: same-selector full durable identity drift and Date-only expiry never return a URL and add zero immediate native/write/close effects. A subsequent explicit original close cleans once and preserves any replaced bytes.
- Existing G1b blocked-close test: retain its read=cancelling versus replay=held assertions unchanged and run it against the external owner to retain a concrete regression.
- Stop writer recovery: fail the first stop writer check, recover the writer before controlled close resolves, then assert zero cleanup writes, unchanged original bytes and held shared credential namespace.
- Missing/corrupt read coverage: actual mocked Date+setTimeout expiry, correctly selected cancel, close, and mutation during blocked close retain required original cleanup and do not resurrect/overwrite. Reuse external missing/replaced positives; add missing fault modes rather than duplicating their five tests.
- Attempted-write uncertainty: real store write-before-throw and write-then-throw for waiting/completed and both cleanup writes. Later cleanup never rewrites those resulting bytes; native cleanup occurs once; shared live custody holds. Cold held/released expectation is derived from actual resourceHeld.
- Ordinary explicit/browser completion, real timer expiry, selector drift cancellation, wrong-selector coherent-receipt controls, shutdown, salted/legacy replay and pending-token races keep existing assertions.
