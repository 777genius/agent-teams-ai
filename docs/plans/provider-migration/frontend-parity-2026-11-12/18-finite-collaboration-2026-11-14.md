## Closed fixture and peer ownership

`desktop-emulated-collaboration-fixture.ts` prepares one disposable
`TEST-desktop-backend-*` root, exact copied/pinned Node wrappers and the three
existing finite peers. Each provider has its original private home, config,
temporary directories and effects journal. The profile captures two initial
members, three provider templates and three management selections. Runtime
and management OpenCode endpoints are distinct loopback reservations. Pin
all peer/helper/wrapper/profile/descriptor bytes before Electron starts.

Existing peer admission remains `TEST_EMULATED_DESKTOP_PROVIDER=1` and the
closed `desktop-ui-v1` protocol. A separate finite collaboration marker may
enable only the new closed message cases; ordinary runtime lanes keep their
original case set. A shared `providerCollaboration.mjs` accepts the original
input and advertised MCP client/tools. It may call only exact advertised
Team tools with their declared arguments, validate replies and append bounded
TEST observations through the peer's existing journal callback. It cannot
open or alter Host/Team stores, select another principal, fake a receipt,
or manufacture Runtime readiness/terminal/custody facts.

Group inputs must carry exactly one original Group context, including the
physical inbound message ID and run key. ACK/reply uses that physical ID as
`relayOfMessageId`; each distinct reply has one retained command ID and UUID
message ID. Direct messages use the original `message_send`. A successful
peer terminal follows confirmed tool results. Unknown markers, unexpected
actors or malformed/duplicate context refuse without writing product state.

## Local diagnostics before Desktop qualification

The original Host smoke exposed concrete protocol differences before the
new UI lane could be admitted. Keep these failed attempts separate from
acceptance evidence:

- Captured Codex launch asks the selected executable for exactly
  `mcp list --json` before starting app-server. The private empty TEST
  configuration now returns an empty catalog through that exact command.
  Its finite child is metadata evidence, not a Runtime allocation.
- The current D encoder supplies a canonical inline TOML `mcp_servers`
  policy and requires `config/read` before `thread/start`. The peer checks
  the exact encoder round trip, Team endpoint/token/tool policy, and native
  local/null defaults. MCP connection follows successful configuration
  verification. Four focused subprocess tests pass, including wrong argv,
  nonempty private config, unexpected Team token and foreign policy refusal.
- The pinned Claude SDK treats a `.mjs` command as a Node script. The
  original captured executable contract requires the wrapper itself; its
  finite Claude wrapper therefore has no script extension and retains the
  existing quoted-Node script header and exact hash checks.
- Main requires a lowercase local provider identifier. The closed OpenCode
  declaration and model route use `test-provider/TEST-model`; TEST display
  labels remain ordinary presentation. No readiness origin is fabricated.
  This lane declares the fixed TEST-only API key in the original project
  and native configurations. Main must observe that credential-backed route
  and the original no-tools native model probe must still succeed. It does
  not claim anonymous local endpoint discovery; no `/models` server or real
  vendor credential is substituted for that separate flow.
- Native OpenCode directory headers use `encodeURIComponent(workspace)`.
  Both finite peers require that exact representation, including ASCII
  paths. Raw/encoded alternatives are not admitted.
- The finite native catalog includes the selected model's API package, ID
  and URL, plus its provider options, derived from the pinned configuration.

- Captured OpenCode Runtime executes the shipped, pinned
  `OpenCodeMcpPolicyPlugin.js` configuration hook before MCP connection.
  The peer accepts only that exact local URL/hash, checks the frozen result,
  and forwards its actual effective headers. It does not reconstruct the
  private nonce or bypass Host's exact policy comparison.
